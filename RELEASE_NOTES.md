# SD-WAN Triage v4.3.2 — Smarter Insights, Accurate Filters

This release focuses on **accuracy**, **educational UX**, and **vendor correctness** — making the tool more trustworthy for junior engineers and more precise for senior staff.

---

## Highlights

### 🐛 Fix: SD-WAN Vendor Detection No Longer Triggers on LAN/Firewall Interfaces

Previously, analyzing a LAN-side PCAP could produce thousands of false SD-WAN vendor matches because shared ports (443, 541, 4500) were treated as strong evidence. This has been completely rearchitected:

- **Dedicated ports** (e.g., VeloCloud UDP 2426, Cisco UDP 12346) are strong evidence
- **Shared ports** (e.g., 443, 4500) now require corroboration from payload signatures, TLS SNI, or HTTP User-Agent
- **Vendors with only weak evidence are pruned** in the `Finalize()` pass

| PCAP | Before | After |
|------|--------|-------|
| `cisco-example-lan.pcap` | 1,137 false positives | 0 vendors ✅ |
| `Velocloud-Lan.pcap` | 5,184 false positives | 0 vendors ✅ |
| `cisco-example-wan.pcap` | Cisco SD-WAN (correct) | Cisco SD-WAN ✅ |
| `Velocloud-Wan.pcap` | VeloCloud (correct) | VeloCloud ✅ |

### 🐛 Fix: Wireshark Filters Are Now Vendor-Specific

The Tunnel Analysis card previously showed hardcoded Cisco Viptela ports (`udp.port == 12346 || udp.port == 12366`) regardless of the actual SD-WAN vendor. Now each vendor gets the **correct** filter:

| Vendor | Wireshark Filter |
|--------|-----------------|
| **Cisco Viptela** | `udp.port == 12346 \|\| udp.port == 12366 \|\| udp.port == 23456 \|\| tcp.port == 23456` |
| **VMware VeloCloud** | `udp.port == 2426` |
| **Fortinet** | `udp.port == 541 \|\| tcp.port == 541` |
| **Aruba EdgeConnect** | `udp.port == 4163 \|\| udp.port == 4980 \|\| udp.port == 4500 \|\| esp` |

The filter is generated by the backend per-tunnel and passed to the frontend — no more static overrides.

### ✨ Feature: "Insight" Badges for Junior Engineers

The sidebar and finding cards now clearly distinguish between **Issues** (actionable problems) and **Insights** (passive observations):

| Type | Badge | Meaning |
|------|-------|---------|
| **Issue** | `3` (solid badge) | Requires investigation — DDoS, rogue DHCP, retransmissions |
| **Insight** | `+2` (subtle badge) | Healthy observation — CDP/LLDP discovery, STP topology, VRRP |

- Finding cards with `severity: Info` now display an **"Insight"** badge instead of "Info"
- Descriptions start with **"Healthy:"** or **"Insight:"** to immediately signal no action is needed
- The sidebar includes a **helper legend** explaining what `+N` means
- Hovering over the `+N` badge shows a tooltip: *"Passive observations, not errors. No action required."*

## All Changes

### Backend (`pkg/`)
- `detector/tunnel.go`: Added Cisco NAT port 12366, Aruba dedicated ports 4163/4980 to Wireshark filter generator
- `detector/sdwan_vendor.go`: Split ports into Dedicated vs Shared, added `Finalize()` pruning (from v4.3.1)

### Frontend (`web/frontend/src/`)
- `types/index.ts`: Added `sdwan_path`, `src_port`, `dst_port`, `confidence` to `TunnelFinding` interface
- `data/knowledgeBase.ts`: Removed hardcoded Cisco Wireshark filter from `tunnel_flapping`
- `components/dashboard/FindingCard.tsx`: Added `wiresharkFilter` override prop; Info severity shows "Insight" label
- `components/dashboard/IssueSidebar.tsx`: Split counts into issues vs insights; added helper legend and descriptive tooltips
- `pages/ResultsPage.tsx`: Educational descriptions for CDP, LLDP, STP, VRRP, SD-WAN vendor, and tunnel findings

### Build & Release
- `build-release.sh`: Rewritten with `-ldflags` version stamping, frontend build step, tar.gz for Unix, zip for Windows
- `README.md`: Added "Smart Insights for Junior Engineers" section with Issue vs Insight explanation and vendor filter table
